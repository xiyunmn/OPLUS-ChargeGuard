# OPLUS 充电温控

面向 OPLUS 设备的充电温控模块，提供 Rust 控制核心与 WebUI。


## 功能

- 全局温控与充电独立预设，分别调整电池、CPU、GPU、DDR 温度目标。默认关闭全局温控、开启充电预设。
- 充电与相机状态事件监听，支持充电期间禁用 Horae 或根据相机状态智能调整。
- 充电预设可独立开启「亮屏快充」，默认关闭。有线充电时让原厂充电消息服务采用息屏判断，减少亮屏附加限流；关闭、满电、拔线或核心退出时恢复真实状态。仍受适配器、温控与功率上限约束，实际提速需真机验证。
- 充电预设可独立开启 PPS 稳定性辅助，默认关闭；保留原厂 PPS Status 电流辅助，并在异常退出、原厂准入条件满足时，有限次请求原厂恢复 PPS。恢复申请使用真实电池温度，达到45℃后需降至44℃及以下；不修改原厂退出阈值、保护票或满电收尾。不限制具体机型，实际恢复效果需真机验证。
- 充电预设可独立开启「售后充电分档」，默认关闭。在电池服务实现与配置兼容且没有在线策略覆盖时，按原厂工程模式调整普通前台场景的充电档位；自动让出 Horae 和温度读数覆盖，相关卡片置灰并保留原设置。进入充电、满电或拔线恢复时会短暂重载系统电池应用。配置已应用不代表实际功率收益已验证。
- 充电预设可独立开启「最大充电功率」，默认关闭、50W、仅SuperVOOC；支持20–100W滑块与SuperVOOC／UFCS／PPS／PD多选。匹配接口的独立内核辅助模块按输入电压施加专属限流上限，原厂允许时尽量接近设定值，保留温控降流和满电收尾。硬件档位与调整延迟会影响实际功率，真机效果需单独验收。
- 支持事件驱动和循环维护两种写入模式，默认事件驱动。Cooling、Bouncing 等使用事件维护；shell-temp、emul_temp、game_opt 保留必要周期维护。
- WebUI 提供仪表盘、温度接口、后端详情和轮转日志，支持浅色／深色主题及 95%～115% 界面 DPI 调节。
- 独立「统计」页提供充电双曲线、历史筛选与数据集导出。上下图可分别选择功率、电流、电压、电量或温度，共用时间游标，支持展开查看及详情范围调整。默认在模块运行时每 5 秒记录充电连接期间的电池读数，保留 90 天原始数据；关闭 WebUI 后继续记录，满电暂停采样。历史每批显示 20 条，支持时间、协议、电量区间及记录完整性筛选。ZIP 数据集包含完整 CSV 采样、事件及当时的系统和配置上下文，保存至 Download。
- 统计功率为电池端净功率，与 USB 输入功率不同。已确认的 OPLUS GKI 接口使用电池 mA／µV 与实际电芯数折算；口径或电芯数未知时显示缺失，不按机型猜测。停止模块、关闭统计及记录中断会保留已有数据并标明原因。
- 支持手动停止、恢复与卸载；不携带 `system.prop`，不修改持久化温控属性。

## 使用

需要已取得 root 权限的 OPLUS ARM64 设备，Android 15 / API 35 及以上，以及支持模块安装的管理器；WebUI 需要相应的管理器入口或兼容宿主。

安装保留 **OPPO、OnePlus、realme** 三品牌或制造商检查，不限制具体机型。安装时进行一次只读能力预检，报告保存至 `/data/adb/charge_guard/capabilities-install.json`；单项不支持不阻止整个模块安装。PPS、功率和亮屏辅助分别核验所需接口、布局、实际ABI和加载代码身份，不以系统指纹、内核版本字符串或整个驱动摘要作为准入条件。关键实现变化仍可能需要适配，预检通过也不代表已经加载或实测。

主要验证设备为 **PJZ110**。跨机型充电效果需另行验收。温度目标和被映射的接口读数不代表真实物理温度。

将 `*_magisk.zip` 交给模块管理器安装，再从 WebUI 配置。详细日志默认关闭，可在排查问题时开启并导出。

## 本地构建

支持 Windows 与 Linux。准备 Python 3.11+、Rust 1.85.1（含 `aarch64-linux-android` 目标）、JDK 17，以及 Android SDK：平台 35、Build Tools 36.0.0、NDK 27.3.13750724。

设置 `ANDROID_HOME` 和 `JAVA_HOME` 后运行：

```sh
python tools/build.py build --channel beta
python tools/build.py build --channel release
```

也可使用 `--sdk`、`--ndk`、`--jdk` 指定路径。产物位于 `target/dist/`，构建不会改写工作区版本信息。依赖按锁文件获取，需要离线构建时显式添加 `--offline`。

## 开发约定

- 优先采用满足明确需求的最小实现，复用现有代码；禁止过度防御性编程，不为假想问题增加兼容层、回退链、重试、状态机、开关或依赖，不顺带重构。
- 保留实际输入、权限、内核 ABI、操作所有权和恢复所需的校验；不把这些运行时约束当作冗余测试删除。
- 禁止后续大量运行测试或新增大量测试代码。只保留少量关键数据与真实故障回归，优先修改现有用例；不运行全量矩阵、WebUI 自动化、全仓 Lint，不通过临时脚本或子代理扩大检查范围。
- 普通文案、样式和可逆小改动不新增测试。仅关键行为变化或明确故障需要短时、定向验证，通过即停止；构建、提交和推送不自动触发本地测试。
- 当前仅保留 8 个用例：原有配置 CAS、修改前保存恢复记录、恢复失败保留记录、充电 XML 字段隔离、设备节点异步创建，以及统计时间／缺失段计算、数据集原始点与导出截止一致性、删除中断后的索引一致性。需要时使用 `python tools/build.py check --test-filter <用例名> --offline`；`check` 不默认运行整套测试。UI 交互检查仅在用户另行明确授权时进行一次定向验收，不扩展为自动化套件。
- 充电效果以真机日志与用户反馈为准，编译或模拟通过不代表实机验收。未经明确授权，不安装、加载辅助模块、切换充电策略或重启设备。
- 仅提交模块源码、必要构建输入及仓库说明；固件、反编译产物、设备日志、测试缓存和本机工具约定留在仓库外或忽略目录。
